# Run Everything in Docker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Before any task, follow the repo's `CLAUDE.md`: this plan changes shared files (root files, `docs/`) and `app/`, so it runs only in a joint session (`We're all three working together…`).

**Goal:** `docker compose up -d --build` starts the lunch app, PostgreSQL and the ngrok tunnel, with data that survives restarts and Teams reaching the bot at a fixed address.

**Architecture:** A two-stage `Dockerfile` builds the existing jar (Maven + its own Node, as in Task 14) and runs it on a Java 21 JRE. `compose.yaml` adds a PostgreSQL service on a named volume and an ngrok service that forwards a fixed domain to the app. The app gains Flyway's PostgreSQL module; everything else is configuration.

**Tech Stack:** Docker / Docker Compose v2, `eclipse-temurin` 21 (JDK for build, JRE for run), `postgres` 17, `ngrok/ngrok` 3, Spring Boot 3.5.16 (Flyway 11.7.2, Testcontainers 1.21.4 as managed by Boot).

**Spec:** `docs/superpowers/specs/2026-11-20-docker-design.md`

**Base branch:** `docker` (from `task-14`, which has the frontend bundling).

## Global Constraints

- Secrets come only from environment variables, via a git-ignored `.env`; never in the image, the repo, or a committed file.
- Variables: `LUNCH_ADMIN_USERNAME`, `LUNCH_ADMIN_PASSWORD_HASH` (BCrypt), `ANTHROPIC_API_KEY`, `LUNCH_TEAMS_SECURITY_TOKEN`, `LUNCH_TIME_ZONE` (default `Europe/Brussels`), plus `POSTGRES_PASSWORD`, `NGROK_AUTHTOKEN`, `NGROK_DOMAIN`.
- Database `lunch` on PostgreSQL, data on the named volume `lunch-db`.
- App port published on `127.0.0.1:8080` only.
- The tunnel uses the fixed `NGROK_DOMAIN`; Teams webhook URL is `https://<NGROK_DOMAIN>/api/teams/webhook`.
- Image runs as a non-root user; image tags pinned.
- `java -jar` with H2 keeps working unchanged (no change to `application.yml` defaults).

## Review Focus

1. **A BCrypt hash in `.env`** (`$2a$10$…`): Compose expands `$` in unquoted `.env` values, which silently corrupts the hash and nobody can log in. Values must be single-quoted; `.env.example` shows it and Task 3 tests login through Compose.
2. **A missing or empty required variable** (`POSTGRES_PASSWORD`, `NGROK_AUTHTOKEN`, `NGROK_DOMAIN`, `LUNCH_ADMIN_PASSWORD_HASH`): `docker compose up` must stop with a message naming the variable, not start half-configured. Task 3 uses `${VAR:?…}` and checks it.
3. **The app starting before PostgreSQL accepts connections**: it must wait, not crash-loop. Task 3 gates on a `pg_isready` health check.
4. **Restarts and rebuilds**: `docker compose down` (without `-v`) followed by `up --build` must keep menu, settings and orders. Task 3 checks a saved setting survives.
5. **Secrets leaking into the image**: `.env` must not be in the build context and no secret may appear in `docker image inspect` / `docker history`. Task 2 checks both.
